# README รายงานงานปฏิบัติการกลุ่ม: Queue Algorithm Design & Analysis with Java

## หัวข้อหลัก: Queue, Circular Queue, Priority Queue, Deque และการประยุกต์ใช้

## กลุ่มที่ 7: Ride-Hailing Driver Assignment — ระบบจับคู่ผู้โดยสารกับคนขับ

### Case Story

ระบบเรียกรถมีผู้โดยสารส่งคำขอเข้ามาเป็น Queue และมี Driver ที่พร้อมรับงาน โดยระบบต้องจับคู่ผู้โดยสาร (Passenger Request) กับคนขับ (Driver) ให้เหมาะสมที่สุดตามเงื่อนไขของแต่ละ Algorithm

### Scenario ที่ใช้ในรายงาน

**Passengers:** R1, R2, R3, R4

**Drivers:** D1, D2, D3

| Passenger | D1 | D2 | D3 |
|---|---:|---:|---:|
| R1 | 5 | 2 | 8 |
| R2 | 1 | 6 | 4 |
| R3 | 7 | 3 | 2 |
| R4 | 3 | 5 | 6 |

**สมมติฐานเพิ่มเติม:** ลำดับการ Request คือ R1 → R2 → R3 → R4 ตามลำดับที่แสดง โดย R1 มาก่อนสุด และคนขับทั้ง 3 คนพร้อมรับงานตั้งแต่ต้น คนขับ 1 คนรับได้ 1 งานต่อรอบการจับคู่

## คำอธิบายโปรแกรม

โครงงานนี้เป็นโปรแกรมภาษา Java สำหรับการออกแบบและวิเคราะห์อัลกอริทึมโดยใช้โครงสร้างข้อมูล Queue เพื่อแก้ปัญหาการจับคู่ผู้โดยสาร (Passenger Request) กับคนขับ (Driver) ในระบบเรียกรถ โดยผู้โดยสารจะส่งคำขอเข้ามาตามลำดับ และระบบจะทำการจับคู่กับคนขับที่พร้อมรับงานตามเงื่อนไขของแต่ละ Algorithm

โปรแกรมพัฒนาและเปรียบเทียบวิธีการแก้ปัญหา 2 วิธี ได้แก่

**Algorithm A: FIFO Matching** ใช้ Queue แบบ FIFO เพื่อจับคู่ผู้โดยสารกับคนขับตามลำดับก่อน-หลังของการเข้ามา

**Algorithm B: Nearest Driver Matching** ใช้ Priority Queue เพื่อเลือกคนขับที่มีระยะทางใกล้กับผู้โดยสารมากที่สุดจากคนขับที่ยังว่างอยู่ โดยจัดลำดับความสำคัญตามระยะทางจากน้อยไปมาก

นอกจากนี้ โปรแกรมยังรองรับกรณีที่จำนวนผู้โดยสารมากกว่าจำนวนคนขับ ทำให้ผู้โดยสารบางคนต้องรอคิว รวมถึงรองรับการยกเลิกคำขอของผู้โดยสารที่ยังอยู่ใน Queue

โปรแกรมมีการทดสอบ Input และ Test Case หลายรูปแบบ เช่น กรณีปกติ Queue ว่าง มีผู้โดยสารและคนขับเพียง 1 รายการ ข้อมูลจำนวนมาก กรณีระยะทางเท่ากัน และกรณีการยกเลิกคำขอ

โปรแกรมยังมีการวัดเวลาในการทำงานด้วย `System.nanoTime()` และนับจำนวน Operation ของ Algorithm A และ Algorithm B เพื่อใช้ในการวิเคราะห์และเปรียบเทียบประสิทธิภาพของอัลกอริทึม

# 1. การวิเคราะห์ปัญหา (Problem Analysis)

## Input

- รายการคำขอผู้โดยสาร (Passenger Request)
  - Request ID
  - Location
  - Request Time
  - Distance ไปยังคนขับแต่ละคน
- รายการคนขับ (Driver)
  - Driver ID
  - Location
  - Available Time
- Distance Matrix ระหว่างผู้โดยสารแต่ละคนกับคนขับแต่ละคน

## Output

- คู่ที่จับคู่สำเร็จ (Passenger–Driver) พร้อมระยะทางของการจับคู่
- รายชื่อผู้โดยสารที่ยังไม่ได้รับคนขับและต้องรอคิวต่อ
- ระยะทางรวมของคนขับทั้งหมด (Total Driver Distance) สำหรับใช้เปรียบเทียบ Algorithm

## Constraints

- จำนวนคนขับอาจน้อยกว่าจำนวนคำขอ ทำให้ผู้โดยสารบางคนต้องรอ
- คนขับ 1 คนรับได้ 1 งานเท่านั้นในรอบการจับคู่ปัจจุบัน
- ต้องประมวลผลคำขอตามลำดับก่อน-หลังของการเข้ามา
- ผู้โดยสารที่มาก่อนต้องมีสิทธิ์ก่อนตามหลัก First-Come
- ระยะทางระหว่างผู้โดยสารและคนขับเป็นค่าคงที่ที่ทราบล่วงหน้า

# 2. Queue Design และ Algorithm Design

## Queue เก็บข้อมูลอะไร

Queue หลักของระบบเก็บข้อมูลคำขอผู้โดยสาร (Passenger Request) เรียงตามลำดับเวลาที่เข้ามา เพื่อรับประกันว่าผู้โดยสารที่ขอก่อนจะได้รับสิทธิ์ประมวลผลก่อน

อีก Queue หนึ่งใช้เก็บคนขับที่พร้อมรับงาน (Available Driver)

## Queue ชนิดที่เหมาะสม

### Algorithm A: FIFO Matching

ใช้ Queue ธรรมดาแบบ FIFO

`Queue<Passenger>`

`Queue<Driver>`

เพราะกติกาคือจับคู่ตามลำดับก่อน-หลัง โดยไม่ต้องจัดลำดับความสำคัญเพิ่มเติม

### Algorithm B: Nearest Driver Matching

ใช้ Priority Queue

`PriorityQueue<Driver>`

เพราะสำหรับผู้โดยสารแต่ละคนต้องเลือกคนขับที่มีระยะทางน้อยที่สุดก่อน โดยระยะทางที่น้อยกว่าจะมี Priority สูงกว่า

# 3. เหตุผลที่ต้องใช้ Queue

คำขอผู้โดยสารในระบบเรียกรถเข้ามาแบบต่อเนื่องทีละคน โดยไม่ทราบจำนวนล่วงหน้า และระบบต้องประมวลผลแบบอัตโนมัติตามกติกาที่กำหนดไว้ เช่น FIFO หรือเรียงตามระยะทาง

Queue และ Priority Queue รองรับการเพิ่มข้อมูลเข้า (enqueue/offer) และดึงข้อมูลออกมาประมวลผล (dequeue/poll) ได้อย่างมีประสิทธิภาพ
